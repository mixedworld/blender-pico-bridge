# Blender PICO Bridge

Read README.md and docs/DEVELOPMENT.md for the supported emulator-first Room setup. Original code is MIT; preserve third-party notices. This is an existing functional prototype, not a new scaffold.

- `blender-addon/pico_blender_bridge/`: Blender exporter, authenticated HTTP server and source-visibility lease.
- `native-app/`: Kotlin/PICO Spatial SDK 6.1.9; read its AGENTS.md before editing it.
- `PROTOCOL.md`: transport authority and content-addressed model revisions.
- `tools/package_release.py`: allowlisted add-on and verified APK packaging.
- `tools/audit_publication.py`: audit the exact Git index before any publication.

Run `python3 -m unittest discover -s tests -v`, the native Gradle unit/build tasks, and publication/package checks after relevant changes. Device/emulator install and source-only tests are separate evidence. Do not claim Windows, hands or headset performance from a Mac build.

Local credentials, evidence, recordings, vendor installs, demo models and generated releases are intentionally ignored. Never add them with force. The local working directory may contain private untracked files; publish only the reviewed Git tree and allowlisted release outputs. No GitHub remote or publication is implied by local preparation.

Source visibility must be scoped to the active Blender view layer. Excluded collection objects can return False from hide_get but raise from hide_set, stopping the timer midway through extraction. source_visibility.py skips absent objects, uses an explicit layer and isolates unavailable-object errors. Preserve original flags on return/lease expiry; tests/test_source_visibility.py covers the regression. Verification: 16 Python tests pass; three live hide/restore cycles preserved visibility and authored transforms in the multi-view-layer scene. The user confirmed on the real PICO that returning the extracted model makes it reappear in Blender and head-tracked viewport synchronization continues.

Direct rendered-viewport streaming (0.5.0) now defaults to Blender RGBA capture: viewport_capture.py owns reversible Cycles view_draw and Eevee GPUOffScreen backends; render_worker.py is an external aiortc/PyAV encoder, isolated from Blender's embedded Python. A bounded anonymous pipe carries latest-only RGBA frames. Never put the token in worker argv/logs. render_stream.py negotiates opaque legacy or color-alpha-top-bottom-v1; the latter packs colour above coverage in one VP8 frame. Preserve scoped authentication, incremental ICE, bounded signaling and keep-alive shutdown. The function imported from render_stream must stay aliased viewport_crop: importing the viewport_capture submodule otherwise replaces a package attribute and kills tick. Cycles camera-ray visibility isolates source geometry and preserves its indirect contribution; Eevee currently streams visible geometry and must not claim collection isolation. Stop/save/load/unregister must restore Film, shading, visibility flags, draw handlers and worker resources. See docs/DIRECT_STREAMING.md. Chrome is an optional opaque compatibility publisher, not the default capture route; do not run both publishers together. New path passed per-backend three-session emulator receive/alpha tests and a production scene live-status test. Physical visual compositing, Windows and latency remain unverified.

Cycles colour correction (0.5.1): color_transform.py uses Blender's active PyOpenColorIO config and working space. Read the Cycles callback buffer as FLOAT; it is scene-linear HDR before viewport colour management. Unassociate before the nonlinear view/look/exposure/gamma transform, preserve alpha, reassociate and only then quantize. Eevee's colour-managed offscreen bytes bypass this step. Select/cache immutable processors on main; apply them to owned NumPy arrays on the bounded pixel writer, with no bpy/GPU calls there. Twelve Blender Image.save_render reference cases match exactly; five in-Blender OCIO regression tests pass. View curves/white balance currently fail clearly instead of silently mismatching. Do not add a blanket receiver gamma correction or restore early UBYTE quantization.

The user visually confirmed the 0.5.1 colour correction in the emulator: streamed brightness and colours now match Blender closely. Keep this evidence separate from the numerical references and from physical-headset verification, which remains pending.
